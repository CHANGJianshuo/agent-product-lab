# ActionTrace 合成评测集说明

`regression.json` 是 ActionTrace 的冻结开发回归集。它用于在没有真人标注条件时比较规则 Baseline 与模型抽取器，并防止修复一个案例后破坏已有能力。

它不是随机抽样的真实聊天记录，也不是独立第三方或真人标注测试集，因此不能用于声称“生产准确率”或“真实用户效果”。

## 数据粒度与构成

- 一条 `case` 是一次独立导入；一条 case 可以包含多条消息和多个事件。
- 共 52 个案例、48 个目标事件、11 个纯负例。
- 事件类型：39 个任务、3 个决策、6 个风险。
- 动作类型：30 个新建、9 个记录、3 个完成、2 个取消、2 个改期、2 个转交。
- 7 个案例提供当前任务，用于验证状态变化与已有任务上下文。
- 案例 ID 和完整输入文本均无重复。

覆盖范围包括明确承诺、负责人或日期缺失、多人多任务、决策、风险、否定、假设、反讽、引用旧消息、Prompt Injection、相对日期、状态变化和重复确认。

## 标注约定

- 只有明确承诺、已达成决策、实际风险或明确状态变化才标注事件。
- 普通讨论、疑问、建议、假设、玩笑、否定和引用旧话不标注。
- 缺失负责人或日期时标为 `null`，不自行补全。
- 只有日期、没有具体时刻时，产品约定截止到当天 18:00（Asia/Shanghai）。
- 每个期望事件记录消息位置、类型、动作，并按需记录标题、负责人和截止时间。

## 指标口径

- 事件 Precision / Recall / F1：候选需匹配消息位置、事件类型，并达到标题相似度下限。
- `change_accuracy`：匹配事件的新建、完成、取消、改期、转交或记录分类准确率。
- `owner_exact_match` / `due_exact_match`：标注字段的严格相等准确率，`null` 也参与比较。
- `title_match`：标准化后的字符相似度达到 0.72；它会把部分语义正确的同义改写计为不匹配。

## 质量判断

该数据集适合：

- 开发期回归测试。
- 比较规则版和 DeepSeek 在同一固定输入上的相对表现。
- 定位否定、日期、负责人、重复任务等失败类型。

使用时必须保留以下限制：

- 数据集和系统提示由同一开发过程产生，存在选择偏差。
- 当前结果是在同一开发集上修正后复跑，不是未见过的 holdout 成绩。
- 决策、风险以及各类状态变化样本数较少，单类指标不稳定。
- 文本相似度不能完整判断两个标题是否语义等价。
- `repeat-message` 按抽取层标了两次事件，而模型只保留一次；从最终避免重复建任务的产品目标看，这个“漏检”存在标签口径争议。
- 即使 temperature 为 0，远端模型也不保证逐次输出完全一致；调优版两次完整运行的 Event F1 分别为 1.0000 和 0.9895，差异来自是否合并重复确认。
