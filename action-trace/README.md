# Converge 0.5（合流）

> 让分歧形成共识，让共识落实为行动。

Converge 是一个本地优先的群体决策与行动闭环工作台。产品只有一个主入口：导入群聊或会议讨论。系统判断内容是“仍需形成共识”还是“已经形成行动”；前者带着原文中的参与者约束与候选方案进入协商，后者进入行动确认，最终汇入同一条可审计链路：**原始依据 → 讨论分流 → 人工确认 → 共识或行动 → 状态跟踪**。

多人决策不依赖大模型，约束校验、满意度、Pareto 前沿和投票排序均由确定性代码完成。DeepSeek 只增强非结构化记录的事件抽取；没有 Key 时产品仍可完整运行，并自动使用本地规则。

## 运行

需要 Python 3.10 或更高版本。只运行规则 Baseline 时：

```bash
python3 server.py
```

然后打开 <http://127.0.0.1:8787>。首次进入可点击“导入聚餐讨论示例”：系统会先从原始群聊生成一份可核对的“需要继续协商”草稿，确认后再进入包含 3 位参与者、4 个方案和私密预算的协商空间。

启用 DeepSeek 智能抽取时，推荐通过环境变量注入密钥：

```bash
export DEEPSEEK_API_KEY="替换为新密钥"
export CONVERGE_EXTRACTOR=auto
python3 server.py
```

也可以复制 `.env.example` 为不会被 Git 跟踪的 `.env.local`。不要把真实密钥写入代码、README、前端或提交记录。默认模型为 `deepseek-v4-flash`，可通过 `DEEPSEEK_MODEL` 修改。

为避免意外费用，单次模型抽取默认最多处理 200,000 个字符；超过后 `auto` 模式会回退本地规则。可用 `DEEPSEEK_MAX_INPUT_CHARS` 调整。

自定义监听地址或端口：

```bash
python3 server.py --host 0.0.0.0 --port 8787
```

数据库默认创建在 `data/actiontrace.db`，以兼容已有 MVP 数据。可通过 `CONVERGE_DB_PATH` 指定其他位置；旧的 `ACTIONTRACE_DB_PATH` 仍兼容。

## 一致的产品流程

```text
导入群聊 / 会议讨论
  → 标准化消息、保留原文位置
  → 判断讨论当前所处阶段
      ├─ 尚未形成共识
      │    → 核对议题、参与者约束和候选方案
      │    → 硬约束过滤 + Pareto 比较
      │    → 多选式认可投票 + 主持人确认
      └─ 已经形成承诺 / 决定
           → 核对动作、负责人和截止时间
           → 人工确认
  → 创建 / 更新正式任务
  → 状态、提醒、报告与审计
```

用户无需先判断该打开哪个功能。系统只负责提出分流建议：讨论尚无共识时进入协商状态，已有明确承诺时进入行动确认；原文证据始终可见，最终判断仍由用户完成。

## 多人决策室流程

1. 用户导入一段聚餐、出游、团建、租房或通用群体讨论；系统识别“尚未达成共识”的议题并生成协商草稿。
2. 用户对照原文核对议题、主持人、参与者和候选方案，确认后才创建协商空间。
3. 系统用讨论中已有信息预填预算上限、最远距离、时间窗口、必须/避开条件、软偏好，以及方案的价格、距离、时间、标签和来源；缺失或错误信息可继续补充修正。预算可以设为私密，公开状态只显示“已设置”。
4. 预算、距离、时间、必须与避开条件作为硬约束。冲突方案会显示具体原因，并且不能进入选票。
5. 系统对可行方案计算逐人满意度。不存在另一个方案能让所有人都不变差且至少一人更满意时，该方案进入 Pareto 前沿。
6. 每个人可以认可多个可接受方案，减少单选投票造成的被迫站队。
7. 推荐顺序依次考虑认可票数、最低成员满意度、平均满意度和成本；主持人仍需在 Pareto 集合中人工确认。
8. 最终决定锁定后，直接创建负责人和截止时间明确的任务，并保留决策、投票、方案与来源证据。

## MVP 能力

- 从讨论记录识别尚未形成共识的议题，生成带原文证据的协商草稿，经确认后预填参与者约束与候选方案。
- 对私密预算脱敏；审计只记录“是否设置”，不记录私密数值。
- 确定性过滤硬约束，计算逐人满意度和 Pareto 前沿，并解释每个冲突与妥协。
- 组织多选式认可投票，由主持人确认最终方案，并一键转为正式任务。
- 导入 `.txt`、`.md`、`.json`，标准化发言人、时间和原始行号。
- 使用 DeepSeek JSON Output 识别复杂任务、决策、风险与状态变化，并对返回结果做本地 Schema、枚举、消息位置和时间证据校验。
- 支持 `auto`、`deepseek`、`rules` 三种抽取模式；智能模式失败会安全回退并留下原因。
- 用可解释的 Baseline 规则识别常见任务、决策、风险、完成、取消、改期和转交。
- 对缺失的动作、负责人或截止时间只生成必要追问。
- 候选事项必须由用户确认；拒绝或未确认的内容不会进入任务看板。
- 更新类事件会匹配现有任务并增加版本，不重复建任务。
- 本地模拟时钟计算临期、逾期和阻塞，生成未发送的提醒草稿。
- 生成带原始文件与行号引用的 Markdown 日报/周报，并导出标准 `.ics` VTODO。
- 记录模型、延迟、Token、规则判断、人工澄清、审批、提交与状态变化；提交接口带幂等键，审计中不保存密钥或完整模型请求。

## 支持的输入格式

文本和 Markdown 推荐使用：

```text
[2026-09-03 09:08] 小林：我来完成登录页视觉稿，明天下午三点前发群里。
2026-09-03 09:14 | 安然 | 麻烦小周下周三前整理访谈反馈。
阿哲：接口联调我来处理。
```

JSON 支持数组，或带 `messages`、`records`、`items` 数组的对象。字段别名包括：

```json
{
  "messages": [
    {
      "speaker": "小林",
      "timestamp": "2026-09-03T09:08:00+08:00",
      "text": "我来完成登录页视觉稿，明天下午三点前发群里。"
    }
  ]
}
```

## 固定回归评测

仓库包含 52 条合成开发回归样例，覆盖承诺、否定、假设、引用、昵称、相对日期、状态变化和 Prompt Injection。它不是人工用户标注集，不能包装成真实实验结果。

```bash
# 零成本运行规则 Baseline
python3 -m actiontrace.evaluate --provider rules

# 用 DeepSeek 跑前 5 条，先控制费用
python3 -m actiontrace.evaluate --provider deepseek --limit 5

# 完整对比并保存可检查结果
python3 -m actiontrace.evaluate --provider all --output artifacts/evaluation.json
```

当前冻结合成开发集包含 52 个案例、48 个目标事件和 11 个纯负例。2026-09-03 的最终同集对比结果如下：

| 抽取器 | Precision | Recall | F1 | 负责人 EM | 截止时间 EM | 累计耗时 | Tokens |
|---|---:|---:|---:|---:|---:|---:|---:|
| 本地规则 | 0.7941 | 0.5625 | 0.6585 | 0.8462 | 1.0000 | 15 ms | 0 |
| DeepSeek | 1.0000 | 0.9792 | 0.9895 | 1.0000 | 1.0000 | 100,932 ms | 37,876 |

首次 DeepSeek 结果为 F1 0.8989；根据失败样本修正通用提示、日期解析和负责人证据验证后，在同一开发集上达到 0.9895。由于这是合成开发集上的同集调优，不是独立 holdout 或真人验证，不得作为生产准确率。完整口径、样本分布和四个残余差异见 [`evals/README.md`](evals/README.md) 与历史产物 [`artifacts/evaluation-report-v0.3.md`](artifacts/evaluation-report-v0.3.md)。

## 隐私与安全

- `rules` 模式完全本地，不会把对话发送给模型服务。
- `auto` / `deepseek` 模式会把本次对话与最多 100 条当前任务的必要字段发送到配置的 DeepSeek API。
- 私密预算不会出现在公开状态、协商卡片或审计参数中；原始导入内容仍保存在本地 SQLite 中，因此部署为多人服务前需要补充访问控制和静态加密。
- 模型只负责生成候选草稿；任务创建、改期、转交、完成和取消仍必须人工审批。
- 聊天里的命令始终是不可信数据，不能改变系统提示、调用工具或绕过审批。
- API Key 只从服务端环境读取，状态接口只返回“是否已配置”。

## 当前边界

当前版本不会抓取微信/QQ、自动搜索餐厅或房源、主动发送消息或创建真实平台任务；候选方案信息需要人工或可信来源提供，`.ics` 只生成本地下载文件。规则模式对“尚未形成共识”的识别刻意保守，表达含糊时应由用户继续整理，而不是擅自创建协商空间。DeepSeek 的合成开发集成绩不等于生产准确率；尚未完成真实多人小组试用，因此群体满意度、整理时间和决策速度等产品指标仍必须标为未验证。
