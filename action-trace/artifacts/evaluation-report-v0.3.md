评测日期：2026-09-03
数据集：`evals/regression.json`
模型：`deepseek-v4-flash`，JSON Output，thinking disabled，temperature 0
总体判断：**可用于开发期模型选择，但对外分享必须附带限制条件。**

## DeepSeek 的四个残余差异

1. `tonight-eight`：事件、负责人和时间正确，标题“把错误日志发出来”与标注“发送错误日志”语义相同，但字符阈值未通过。
2. `delay-risk`：风险识别正确，模型标题保留了“周五发布可能来不及”的原句表达，字符匹配未通过。
3. `explicit-blocker-and-owner`：任务与风险均正确识别；风险标题是解释性同义改写，字符匹配未通过。
4. `repeat-message`：两条连续消息表达同一个承诺，标注期待两个抽取事件，模型主动保留一个，因此形成唯一 FN。产品提交层本身会去重，所以这不一定是用户可感知错误。

## 调优记录

首次完整调用中，DeepSeek 的 Event F1 为 0.8989。失败分析后进行了以下通用修复：

- 明确无截止日期的承诺仍需抽取。
- 一条消息中的任务、风险和后续新承诺必须分别输出。
- 加强完成表达和实际阻塞风险识别。
- 修正带空格的中文日期、“今晚八点”和 ISO 日期 + 时刻解析。
- 防止把消息发送者未经证据直接推断为负责人。
- 补充中英文第一人称承诺验证。
- 将远端主动断开纳入安全重试。

调优后 F1 为 0.9895，提高 0.0906。由于修复和复跑使用的是同一数据集，该提升只证明回归问题被修复，不证明对未见真实数据有同等提升。

另一次相同调优版完整运行得到 F1 1.0000；两次差异仅在 `repeat-message` 是否保留第二条重复确认。temperature 0 降低随机性但不保证远端服务逐次完全一致，因此当前表格固定采用最后一次可复查快照，不挑选最高成绩。

## 决策

- MVP 默认继续使用 `auto`：DeepSeek 优先，本地规则故障回退。
- 人工确认、字段证据和幂等提交不能因为开发集成绩较高而移除。
- 当前结果足以证明 DeepSeek 相对规则 Baseline 更适合复杂语义抽取。
- 当前结果不足以支持生产准确率、用户节省时间或真实闭环率等对外结论。
