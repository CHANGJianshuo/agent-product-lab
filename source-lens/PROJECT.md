# SourceLens：截图/短视频多模态溯源 Agent

## 1. 项目定位

- 目标方向：腾讯 PCG / 搜索 / 内容生态 / 可信信息
- 当前状态：可运行 Agent Demo（M1–M3 已完成）
- 一句话：从截图、转发文本或短视频中提取可验证主张，自主寻找原始出处和权威证据，交付可复核的证据链，而不是只给“真/假”结论。

本项目的核心竞争力是证据溯源、时间与上下文判断、置信度校准，不是普通联网问答。

## 2. 用户与问题

目标用户：经常接触群聊转发和短视频信息的学生、内容编辑、自媒体审核者。

核心问题：

- 截图丢失链接、作者、时间和上下文。
- 一段内容可能包含多个真假混合的主张。
- 搜索结果中的转载可能互相引用，数量多不代表独立证据多。
- 模型容易在证据不足时给出过度确定的判断。

## 3. MVP 范围

### 必须实现

1. 支持图片截图和文本输入；视频第一版可使用已有字幕或短音频转写适配器。
2. OCR/解析后拆分为原子化、可验证主张。
3. Agent 为每条主张生成检索计划，调用搜索和网页读取工具。
4. 对来源进行权威性、独立性、时间相关性和一手/转载分类。
5. 检测旧闻翻炒、断章取义、主体混淆和图片文字不一致。
6. 输出结论、证据卡、反方证据、未知项和校准置信度。
7. 每条重要结论必须能追溯到具体来源片段。

### 暂不实现

- 给用户或账号贴“造谣者”标签。
- 在证据不足时强行二分类。
- 自动发布辟谣内容或举报账号。
- 自建大规模搜索引擎和视频理解模型。
- 医疗、法律、投资等高风险领域的最终判断。

## 4. Agent 闭环

```text
截图/文本/视频字幕
  → 提取主张与实体
  → 重建结论、前提、假设与论证类型
  → 独立反方审稿并规划证伪查询
  → 为不同主张规划检索
  → 搜索、打开来源、追踪原始出处
  → 比较时间、上下文和来源独立性
  → 识别证据缺口并继续检索或停止
  → 输出可复核证据图谱与不确定性
```

推荐工具：

- `extract_text_from_image`
- `extract_atomic_claims`
- `search_web`
- `open_source`
- `find_original_source`
- `archive_snapshot`
- `score_source_quality`
- `build_evidence_graph`

网页内容是不可信数据，不得将网页中的指令作为系统指令执行。

## 5. 建议架构

- 前端：上传区、主张列表、证据时间线和来源关系图。
- 后端：主张、检索任务、来源、证据关系和最终判断分层存储。
- OCR/ASR：适配器模式，允许先用本地或云端服务。
- 搜索：至少一个搜索 Provider；缓存结果以保证评测可复现。
- Agent：限制搜索轮数和总预算；证据充分或边际收益过低时停止。
- 引用：存储 URL、标题、发布时间、访问时间和支持该主张的片段。

## 6. 数据与评测

建立至少 50 个样本，覆盖真实、错误、部分真实、旧闻、无证据、截图裁剪和多个主张混杂。

核心指标：

- 原子主张提取 Precision/Recall/F1
- 引用有效率与引用蕴含率
- 原始来源发现率
- 证据覆盖率
- 无依据断言率
- 结论准确率与置信度校准误差
- 平均搜索轮数、延迟和成本

评测中应区分确定性代码检查、人工标注和 LLM Judge，不能只依赖模型自评。

## 8. Definition of Done

- 用户可上传截图并获得多主张、逐条引用的报告。
- 所有引用可点击且能定位到支持内容。
- 证据不足时明确输出未知，不虚构来源。
- 固定评测集可比较 Baseline 与 Agent 版本。
- 网页 Prompt Injection 测试不会改变系统行为或触发非检索工具。

## 9. 简历交付物

- 可交互的证据时间线/关系图
- 一次旧闻翻炒或断章取义的完整溯源演示
- 引用准确率、证据覆盖率与校准曲线
- 搜索停止策略和来源质量模型说明
- 失败案例与伦理边界说明
